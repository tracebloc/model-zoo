# Engine dependency pin for prepping AND verifying offline weight dumps.
# backend#2641 / backend#2658.
#
# WHY THIS FILE EXISTS
# --------------------
# A prepped <base>_weights.pkl state_dict's key layout is decided by the
# transformers/timm/torchvision version that built the module tree, and the
# engine strict-loads seeds (load_state_dict(strict=True)). So prep and
# verification MUST run against the exact versions the engine runs, or a dump
# is a silent edge-only training abort (backend#2641).
#
# SINGLE SOURCE OF TRUTH = the engine, NOT this file.
# These pins mirror tracebloc-engine `use_cases/requirements.txt` and
# `use_cases/requirements_cuda.txt` (torch/torchvision). The CI gate
# (.github/workflows/verify-dumps-engine-pin.yml) checks out the engine and
# FAILS if any line below drifts from the engine's pin — so an engine
# `transformers` bump turns the gate red until this mirror (and then the staged
# dumps) are regenerated, instead of silently invalidating hosted seeds.
#
# Only the dump-key-layout-determining libraries are listed. The engine's
# heavier runtime deps (azure-servicebus, opencv, pandas, telemetry, …) do not
# influence a module tree's state_dict and are intentionally omitted; GPU-only
# libraries (torchao, bitsandbytes) likewise. If a template ever needs one of
# those to *construct*, add it here and the drift guard will keep it honest.
#
# HOW TO PREP A DUMP
# ------------------
#   python -m venv .prep && . .prep/bin/activate
#   pip install -r tools/requirements-engine-pin.txt
#   python tools/prep_offline_weights.py --prep … --ship … --out …
# and record these versions in manifest.json's schema-2 `built_with` block.

# CPU wheels — CI runs on CPU runners; the engine's edge torch pin is the same
# version (use_cases/requirements_cuda.txt), only the build variant differs.
